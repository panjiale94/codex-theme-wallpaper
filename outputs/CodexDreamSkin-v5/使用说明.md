# Codex 动态皮肤 v5：自动恢复与轻量守护

## 1. 需求与修复

让关闭设置窗口、完整退出 Codex 再打开，以及重新登录 Windows 后都能够恢复上次主题，同时减少后台常驻内存。

本机原失效原因是普通 Codex 启动入口没有携带本机主题连接参数。旧后台还保留失效的页面连接和大块 Base64 媒体。部分加密配置目录无法可靠地覆盖重命名文件，也可能造成启用状态保存失败。

## 2. 方案

- 设置界面与守护拆为两个进程。后台为无 WPF 的 .NET 小型程序，关闭设置窗口后不保留界面进程。
- 媒体按 16 KB 分块送入 Codex，由浏览器创建 Blob URL；后台仅保存当前文件路径，不保留整张图或视频的 Base64 副本。
- 登录 Windows 时仅启动轻量守护，等待用户打开 Codex。
- 启用主题时创建桌面和开始菜单“Codex（动态皮肤）”快捷方式，识别可支持的已有 Codex 快捷方式并备份后接管。
- 设置与页面登记记录使用当前用户注册表保存，兼容旧版 JSON 设置读取。关闭效果时撤销登录启动、还原被接管的快捷方式并停止守护。

## 3. 使用与部署

**请使用完整软件包，保留以下结构：**

```text
CodexDreamSkin.exe
CodexDreamSkin.Worker.exe
Themes/
  center-shrine.png
  ...（共 9 张原始主题图片）
```

1. 解压到固定目录，双击 `CodexDreamSkin.exe`。
2. 选择主题并点击“应用主题 / 启动 Codex”。Windows 登录自动恢复默认勾选，可自行关闭。
3. 升级时若当前 Codex 没有主题连接参数，先使用 Codex“文件 → 退出”退出一次，再从桌面 **Codex（动态皮肤）** 打开。
4. 以后用该入口打开 Codex，主题自动恢复；也可将这个快捷方式固定到任务栏。
5. 关闭设置窗口后可继续播放。需要关闭时重新打开设置，点击“关闭效果”。

重新启动电脑并登录后，守护会自动启动，用户打开 Codex 时恢复原主题。纯 Microsoft Store 应用列表入口可能不支持携带连接参数，应使用自动恢复快捷方式。应用自身正常重启时能够保留启动参数。

## 4. 本机配置

- 设置和页面记录：`HKCU\Software\CodexDreamSkin\Profiles`，按用户资料目录区分。
- 登录启动：`HKCU\Software\Microsoft\Windows\CurrentVersion\Run\CodexDreamSkin`。
- 日志和原快捷方式备份：`%AppData%\CodexDreamSkin`。
- 主题连接仅使用 `127.0.0.1`，命名管道限制为当前 Windows 用户。
- 不安装 Windows 服务，不修改 Codex 安装包，不提前在后台启动 Codex。

## 5. 验收与内存

已验证：刷新恢复、完整退出后重开、四主题 GPU 动效、视频分块加载、模拟 Windows 登录后恢复、禁用后登录不驻留后台，以及真实 HKCU 登录启动与快捷方式的撤销和恢复。

同一台电脑上，旧后台工作集约 222 MB；新后台等待时约 43 MB，播放测试约 65～70 MB，私有提交约 11～35 MB。数据是本机样本，实际占用随窗口数、媒体与系统变化。新后台未加载 WPF，强动效仍为 155 个背景粒子并保留 GPU 风场。

登录恢复通过“关闭守护和客户端 → 启动登录守护 → 打开客户端”模拟验证，没有实际重启用户电脑。

## 6. 限制与排查

- 软件目录需保留。移动后重新打开设置并应用一次，可更新登录启动和快捷方式路径。
- 原生 Store 入口不携带主题连接参数时不能恢复；请使用恢复快捷方式。[Electron 启动参数说明](https://www.electronjs.org/docs/latest/api/command-line-switches)。
- 日志可查看连接或素材错误。PNG / GIF / MP4 / WebM 等媒体仍受单文件 100 MB 限制。
- Windows 禁用该登录启动项时，需要在系统启动设置中恢复启用。
- 高强度特效仍会使用 Codex 渲染进程的 GPU 和图像内存；本次优化后台进程，不降低动效强度或画质。
