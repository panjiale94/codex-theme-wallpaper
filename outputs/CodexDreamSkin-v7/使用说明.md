# Codex 动态皮肤 v7：登录恢复与异常自愈

## 1. 需求分析

关机后重新登录 Windows，再普通打开 Codex，自动恢复上次主题；设置窗口关闭后继续运行，并保持强动效与较小的后台内存。

本次现场发现：启用状态和旧 Run 启动项都存在，但没有守护进程，也没有本次启动日志。仅登记 Run 项不足以确认开机恢复。另经真实计划任务验证，本机用户目录下新安装的 EXE 无法被该任务找到，迁移到 ProgramData 后可正常启动。

## 2. 方案选型

- 当前用户交互式计划任务：登录、解锁时启动；每分钟检查，守护异常退出后重新拉起。
- 当前用户启动文件夹提供备用入口；互斥锁保证只有一个常驻守护。
- 守护和 9 张主题图片安装到 `ProgramData\CodexDreamSkin\Users\<当前用户 SID>\Runtime\<内容标识>`，不依赖 D 盘开发目录。
- 配置和连接记录统一存储在该用户目录的 `Profiles` 下，原子替换；旧注册表和 JSON 用于迁移，注册表保留兼容镜像。关闭效果状态由所有启动入口共同读取。
- 运行目录仅授予当前用户、SYSTEM、管理员访问权限。复制逐文件 SHA-256 校验；内容独立目录避免覆盖正在运行的 EXE。
- 保留无 WPF 守护及 16 KB 媒体分块，不降低粒子、GPU 风场或图片画质。

## 3. 部署与配置

完整解压软件包，保留 `CodexDreamSkin.exe`、`CodexDreamSkin.Worker.exe` 和 `Themes` 文件夹。

打开设置，选择主题并应用，保持“Windows 登录后自动恢复”勾选。首次应用会安装运行副本、登记计划任务及备用启动入口。之后可以关闭设置窗口。

关闭效果时重新打开设置并点击“关闭效果”：撤销计划任务、备用入口及被接管的快捷方式，停止守护。取消登录恢复勾选会撤销登录启动，但不立即关闭当前主题。

命令行修复启动项：

```powershell
.\CodexDreamSkin.Worker.exe --repair-startup
```

该命令按已保存的启用状态修复配置，不强制启用已关闭的效果。

## 4. 本机参数

- 计划任务：`CodexDreamSkin.AutoRestore`，当前用户、InteractiveToken、普通权限；运行时间不设上限，电池供电时不停止，重复实例忽略。
- 备用入口：Windows 当前用户启动文件夹中的 `CodexDreamSkin AutoRestore.lnk`。
- 旧 `Run\CodexDreamSkin` 启动值迁移后移除。
- 主配置：`ProgramData\CodexDreamSkin\Users\<当前用户 SID>\Profiles`；兼容镜像：`HKCU\Software\CodexDreamSkin\Profiles`。
- 已安装守护路径：`HKCU\Software\CodexDreamSkin\InstalledWorker`。
- 日志：`%AppData%\CodexDreamSkin\skin.log`。
- 通信：当前用户专用命名管道，连接 Codex 的 `127.0.0.1` 调试端口。

## 5. 调试步骤

1. 应用主题，检查计划任务存在，动作指向 ProgramData 的守护。
2. 执行该计划任务，检查任务处于运行状态、守护命名管道能够返回 v7。
3. 结束守护进程，等待下一次检查，应在约一分钟内重新启动。不要结束 Codex 工作进程。
4. 退出再普通打开 Codex，应恢复主题。当前没有主题连接的旧工作实例不会被强制重启。
5. 点击关闭效果，计划任务和备用入口应被撤销，之后登录不再启用。

验收脚本：`work/test_logon_integration.ps1`（真实计划任务）与 `work/test_native_logon_v7.ps1`（独立资料目录的原生启动、动效与视频）。

## 6. 潜在风险与限制

- 尚未实际重启用户电脑；真实计划任务执行和守护崩溃恢复验收不能替代整机重启验收。
- 系统策略或用户禁用全部自动启动入口时，需重新启用。守护恢复存在检查间隔。
- Codex 未带主题连接参数时，新启动阶段可能快速重开一次。超过 15 秒的旧工作实例不会自动重启，首次升级后可在工作完成时退出重开。
- 若守护恢复较晚，Codex 已运行超过 15 秒，也需退出重开一次；不能通过强制中断旧工作来掩盖这一限制。
- 计划任务不可注册的环境会保留启动文件夹入口并记录原因；异常自愈需要计划任务可用。
- 运行文件安装副本约 90 MB 磁盘空间，不表示常驻内存；旧运行版本不会自动删除。
